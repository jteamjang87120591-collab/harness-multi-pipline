# 관점별 체크 항목 예시 모음

본문(SKILL.md)에 다 담으면 길어지므로, 관점별 항목 아이디어를 여기로 분리한다. 새로운 도메인의 변경을 만났을 때 참고하되, **변경에 실제 해당하는 항목만** 골라 쓴다.

## 🐛 버그
- 입력이 null/undefined/빈 컬렉션일 때 분기가 정의되어 있는가?
- 반복문 경계가 off-by-one 없이 정확한가? (`<` vs `<=`)
- 비동기 호출의 실패(reject/throw)가 처리되는가?
- 변경된 함수의 기존 호출부가 새 시그니처/동작과 호환되는가?
- 동시성: 공유 상태를 읽고 쓰는 경로에 경쟁 조건이 없는가?

## 📖 가독성
- 변수/함수 이름이 의도를 드러내는가? (`data`, `tmp` 같은 모호한 이름 회피)
- 한 함수가 한 가지 책임만 지는가?
- 주석이 "무엇"이 아니라 "왜"를 설명하는가?
- 매직 넘버가 이름 있는 상수로 분리되었는가?

## 🧪 테스트
- 추가/변경된 모든 분기에 대응하는 테스트가 있는가?
- 엣지 케이스(빈 입력, 최대/최소값, 실패 경로)가 커버되는가?
- 테스트가 구현 세부가 아닌 동작(behavior)을 검증하는가?
- 외부 의존성이 적절히 모킹/격리되었는가?

## 🔒 보안 (해당 변경에 보안 표면이 있을 때만)
- 외부 입력이 신뢰 경계에서 검증/이스케이프되는가?
- 비밀값(키, 토큰, 비밀번호)이 코드/로그에 하드코딩되지 않았는가?
- 권한/인증 확인이 우회 가능한 경로가 없는가?
- SQL/명령/경로 주입 표면이 파라미터화/정규화로 막혔는가?
- 에러 메시지가 내부 구조나 계정 존재 여부를 과도하게 노출하지 않는가?
